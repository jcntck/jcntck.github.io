## Implementação e validação local

- Diretriz de entrega registrada em AGENTS.md e contexto OpenSpec: PR aberto junto à liberação inicial para teste; toda alteração pedida nesse ciclo é patch fix sem nova confirmação de versão.

O titular informou inicialmente que ainda estava configurando o console; posteriormente homologou a entrega. Nenhum serviço externo foi provisionado pelo agente; não foram importados Storage, Firestore ou Analytics.
- SDK Firebase `12.19.0`, App `0.16.2` e App Compat `0.5.18` compatíveis com Node 22; override gRPC `1.14.7` corrige dependência transitiva. Instalação limpa pelo lockfile sem avisos de engine; auditoria sem vulnerabilidades.
- Lint, tipos, build e validação estrita OpenSpec aprovados. 57 testes Vitest e 8 testes do processo de release aprovados. 12 testes Chromium locais em desktop/celular aprovados.
- Testes de navegador incluem fluxo completo com fetch nativo, login/Drive independentes após refresh, saída entre abas e prazo de 30 dias. Um cenário usa o SDK Firebase real com emissão/renovação REST simuladas para conferir persistência e remoção do login. As fixtures não entram no build público.
- Prazo de 30 dias verificado com relógio controlado; isso não representa uma espera real de 30 dias. Consentimento e sessão reais foram aceitos pela homologação do titular, distinta das simulações automatizadas do agente.
- Inspeção do build sem fixtures, tokens sintéticos ou credenciais privadas. Configuração Firebase/OAuth é pública e esperada; credenciais de usuário não são incorporadas ao artefato. A persistência de login é gerenciada somente pelo SDK; Drive, documentos e rascunhos ficam em memória.
- Na produção, os 6 testes de shell rodam contra o artefato publicado; os 6 cenários de fixture Auth são exclusivos da validação local/CI. A homologação real do login e Drive não é substituída por esses testes.

## Fix 0.3.1 — Foto de perfil no menu

Solicitação de revisão do usuário: reaproveitar a foto Google mantendo o layout do menu. A apresentação recebe `photoURL` do perfil autenticado e usa o círculo de 32 px do cabeçalho, preservando nome, Trocar conta e Sair. Sem foto ou após erro, mostra iniciais. A foto não é copiada para o repositório nem para storage próprio. Pacote, lockfile e alvo atualizados para `0.3.1`; mesma entrega no PR #3, sem tag antes do merge.

Validação do fix: lint, tipos, 57 testes Vitest, suíte de release, build e 12 testes Chromium aprovados. O cenário com SDK Firebase real/REST simulado verifica carregamento da foto, preservação após refresh e iniciais após falha, sem dados pessoais reais. Nenhuma nova configuração ou permissão Google necessária.
