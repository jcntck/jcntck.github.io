## Configuração remota observada

A consulta realizada nesta implementação encontrou o ruleset `PROD` desativado e `main` sem proteção efetiva. É necessário ativar PR e o check `Dev checks` como obrigatórios antes do merge. O conector GitHub disponível não oferece alteração administrativa de rulesets.

No ruleset existente há também a regra **Restrict updates** sem atores de bypass. Ela bloqueia atualizações, inclusive merges; para o fluxo aprovado, configurar a proteção usando PR e checks obrigatórios, preservando as regras de não exclusão e de não force-push.

## Recuperação

Na primeira entrega não há versão anterior de produção. Após publicar, exercitar **Actions → Prod → Run workflow**, branch `main`, tag `v0.1.0`. Confirmar que a mesma tag e o mesmo SHA são preservados e que o site continua apresentando `0.1.0`.

Não registrar esse exercício como rollback para uma versão anterior. A partir da próxima release, a mesma entrada manual permite selecionar uma tag anterior conhecida.
